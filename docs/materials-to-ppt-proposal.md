# 素材与需求 → 本地模板选择 → PPT 制作方案

日期：2026-10-16。状态：讨论稿。输入范围、模板来源、制作前确认方式已由用户确认；下述实现设计为建议方案。

2026-10-16 落地进展：用户授权建设首批模板库，现已从官网入库 5 套模板，详见相邻 [本地候选模板库](../../powerpoint-template-library/README.md)。120 页主副本与 17 页技术测试已渲染评审，完整工具测试为 48 项通过。渲染需在允许 LibreOffice 运行的环境执行。素材读取与推荐流程仍属于后续阶段。

目标：用户提交素材和需求，Agent 整理内容、从本地模板库选择适合的整套模板，展示推荐理由和页纲；按当前用户指令决定是否先审阅页纲，在该模板上完成 PPT，并进行内容与逐页视觉验收。

## 已确认的产品边界

- 模板来源：本地模板库优先；没有适合模板时提示缺口。
- 制作交互：展示推荐依据；用户要求审阅时先展示页纲并等待确认，否则继续生成和验收。
- 素材范围：文字说明、Word、PDF、Excel／CSV、图片；扫描件 OCR 后续支持。
- 首期沿用当前 Hermes Agent + PowerPoint skill 的交互方式。

## 用户流程

1. 提交素材和需求。提取主题、受众、目的、页数或时长、语言、风格、必需内容、原生可编辑图表等约束。会影响内容真实性或模板可行性的缺失信息先澄清；一般偏好使用明确列出的默认值。
2. 整理素材。形成可追溯的事实、数据、图片及来源清单，生成内容骨架，例如“封面、背景、三项成果、数据对比、问题、行动计划”。此时先确定表达需要，不绑定具体模板页面。
3. 推荐模板。先检查硬性约束，再按内容适配程度与视觉偏好排序；展示 1 个主推荐和最多 2 个备选。只展示满足基本制作条件的候选，候选数量不足时如实说明。
4. 展示可评审方案。提供模板预览、选用理由、逐页标题与要点、采用的页面类型、主要素材来源和尚缺内容；用户可更换模板或调整页纲。用户无需阅读 JSON。
5. 按当前约定生成。将页纲与模板内具体页面和 shape 对应，编译成现有 `powerpoint.plan/v1`，复制需要的页面、填充内容、删除不用的页面、调整顺序并输出 PPTX。
6. 验收与修订。检查内容覆盖、数字与来源、模板示例内容残留、图片比例、文字溢出及遮挡；修改计划后重新生成和检查。交付 PPTX、页面预览与简短验收说明。

确认绑定所选模板版本、页纲和关键约束。修复错字、适当缩短表述等在已确认范围内的调整可直接完成；更换整套模板、改变约定页数范围、删减必需内容时重新展示受影响方案。

## 模板库与选择依据

建议模板素材独立存放在工作区的 `powerpoint-template-library/`，与源码、评测产物分离。每套模板入库时生成以下档案：

- 模板 ID、文件 SHA、版本、来源、尺寸、字体与视觉风格、适用场景。
- 逐页预览与用途：封面、目录、分节、列表、图文、对比、时间线、数据、总结等；一页可支持多种用途。
- 每页可编辑区域的严格 locator、语义角色、类型、保留区域与需替换的示例内容。
- 文本容量建议、图片宽高比、表格行列数、原生图表类型、可复用方式及已知限制。
- 结构检查与渲染评审结果；模板文件变化后根据 SHA 重新建档。

语义角色由 Agent 结合 inventory 和页面预览提出，并在入库时校验。运行时使用已校验的严格引用。字符数只能作为容量预警，实际能否放下以渲染为准。

选择分为两层：

1. 整套模板匹配：先检查尺寸、必需的可编辑对象、可用页面组合及渲染条件，再比较内容类型覆盖、信息容量、图片比例、风格和预计修改量。
2. 模板内部逐页匹配：为每个内容页选择可承载它的示例页，决定复用、复制或拆页，并绑定对应槽位。若无法形成满足硬性要求的逐页计划，该模板不能作为完全匹配候选。

首期一份成品使用同一套模板，保持母版与视觉风格一致。选择理由应能具体解释，例如“该模板有三项成果页和双栏对比页，能承载现有内容，且字体适合中文汇报”。

当前本地库已有 5 套候选模板、120 页，另保留 `template1.pptx` 用户模板基线。后续重点是接入素材读取、能力筛选和推荐评测。

## 素材、事实与容量处理

- Word 提取段落、表格和图片，保留段落／表格位置；PDF 首期处理可提取文字的文件并保留页码。扫描 PDF 明确提示尚需 OCR。
- Excel／CSV 保留表头、数值、单位与来源位置；公式结果缺失、表格结构不清晰时列出问题，不猜测数值。
- 图片记录尺寸、用途和来源；Agent 判断内容与页面的关联，图片中的精确数值不作为已验证的数据替代品。
- 内容提炼允许归纳与改写，数字、结论及用户要求保留的表述必须能追溯到素材。素材缺少的必需事实先补齐，或由用户明确调整要求。
- 文本放不下时，优先压缩冗余表达、换用更合适的模板页面或在约定页数内拆页；保留必需信息。按字体和字数估计的容量检查后，仍需逐页渲染。
- 原生可编辑表格／图表属于明确约束时，模板需要具备相应对象和可执行页面组合。当前执行器要求表格尺寸匹配，拒绝复制含原生 chart 的页面；匹配阶段必须计入这些限制。`template1.pptx` 的原生 table/chart 数量均为 0。
- 缺少合适模板时展示具体缺口与可补充的模板类型；调整呈现方式需要用户确认，不能自动把必需的可编辑图表降为图片。

## 建议的实现接口

新增资料与现有执行 plan 分开记录，继续使用现有执行契约：

| 文件 | 作用 |
| --- | --- |
| `materials.json` | 文件、事实、数据表、图片及来源位置；提取问题与缺口 |
| `brief.json` | 用户目标、硬性要求、偏好、默认值和必需内容 ID |
| `template-profile.json` | 模板及逐页语义档案，绑定文件 SHA |
| `presentation-plan.json` | 候选模板、推荐理由、所选模板、逐页内容、素材来源与确认状态 |
| `plan.json` | 编译出的现有 `powerpoint.plan/v1`，供执行器使用 |
| `qa-report.json` | 要求到可见页面的覆盖关系、来源核对、结构及视觉评审状态 |

首期实现按素材读取、模板注册与检索、内容规划与映射、plan 编译、质量验收划分。具体脚本命名与新增 Schema 在进入实现时确定。

## 实施顺序与验收

1. 修复或配置渲染运行环境，使已有渲染测试与真实模板预览成功；建立首批模板档案。
2. 实现素材读取、需求与来源清单、模板筛选和页纲展示，先验收“推荐是否合理、方案是否覆盖需求”。
3. 将确认后的方案编译到现有 plan，完成生成、读取回验、逐页检查与修订。
4. 用多模板、多素材任务做完整评测，并将新流程写入技能说明。

至少覆盖以下验收场景：文字较多的汇报、图片较多的介绍、数据对比汇报、超出页面容量的素材、没有符合硬性要求的模板，以及用户修改推荐模板或页纲后重新生成。

通过条件包括：推荐依据与实际模板能力一致；必需内容出现在可见页面；数字与来源一致；模板示例文字、旧日期与无关示例数据已处理；原生可编辑性满足要求；全部页面渲染并逐页审阅。结构通过和视觉通过分别记录。渲染失败的结果标为未完成视觉验收，不能作为通过的成品案例。

当前评测仅检查关键词、页数、对象数量等，且关键词包含备注；需要新增逐项的可见内容验收。完整验收保留素材清单、模板档案、确认后的页纲、执行 plan、最终 PPTX、渲染清单及评审记录。
